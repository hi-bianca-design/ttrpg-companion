# Auth — PRD
**Date:** 2026-05-15
**Status:** Approved
**Module:** Auth (Sign-Up · Login · Profile)

---

## Overview

Auth covers account creation, login, session management, and profile management. Three sign-in methods are supported: email/password, Discord OAuth, and Apple Sign-In. The module handles first-time onboarding (username setup), email verification (soft gate), password recovery, and account deletion with campaign data preservation.

---

## Non-Goals

- **Social profile features** — following other users, public profiles, or activity feeds are out of scope; profiles are functional identity only
- **Two-factor authentication (2FA)** — not required for v1; the Discord and Apple OAuth paths already carry their own auth security
- **Username history** — no record is kept of previous usernames; changing a username updates all references immediately
- **Admin / moderation tools** — no ability for one user to manage or ban another; all accounts are equal
- **Guest / anonymous access** — all app features require an account; there is no try-before-you-sign-up mode

---

## User Stories

### New user signing up

- As a new user, I want to sign up with my email and password so that I can create an account without needing a third-party service
- As a new user, I want to sign up with Discord so that I can use my existing gaming identity without creating a new password
- As a new user, I want to sign up with Apple so that I can create an account privately without sharing my real email
- As a new user after signing up, I want to be prompted to set my username before accessing the app so that my identity is established before I interact with other players
- As an email/password user, I want to be able to use most of the app before verifying my email so that I can explore the app without being blocked at the gate

### Returning user logging in

- As a returning user, I want to stay logged in indefinitely so that I don't have to re-authenticate every time I open the app between gaming sessions
- As a user who forgot their password, I want to receive a 6-digit code by email and reset my password entirely within the app so that I'm not dependent on deep links working correctly on my device
- As a user whose device was lost or stolen, I want to sign out all active sessions from any device so that I can revoke access remotely

### User managing their profile

- As a user, I want to update my display name and avatar so that my party members see an up-to-date identity in campaign views
- As a user, I want to change my username so that I can update my handle if it no longer fits
- As a user deleting their account, I want to be clearly told that my campaign data will be preserved for my party members so that I understand the consequences before confirming

## Requirements

### P0 — Must Have

- **Three sign-in methods** — email/password, Discord OAuth, Apple Sign-In; all presented on sign-up and login screens
  - *AC:* All three methods successfully create or authenticate an account; Discord and Apple users are marked as verified on creation
- **Username setup screen** — hard gate after first sign-up for all methods; user cannot access the app until a unique username is set
  - *AC:* New users on all three auth paths land on username setup before the home screen; the screen cannot be dismissed or skipped
- **Unique username enforcement** — username must be unique across all users; real-time availability check on input
  - *AC:* Submitting a taken username shows an inline error; a unique username saves successfully
- **Email verification soft gate** — unverified email/password users see a persistent banner; campaign actions (create/join) are locked until verified; Discord and Apple users are exempt
  - *AC:* Unverified email users see the banner and cannot access campaign creation or joining; Discord/Apple users see no banner; tapping "Resend email" sends a new verification email
- **Password reset via OTP** — "Forgot password?" triggers a 6-digit code sent to the user's email; code entry and new password are set entirely in-app
  - *AC:* Valid code + new password logs the user in automatically; invalid or expired code shows an inline error; resend is available after 60 seconds
- **Indefinite sessions** — users remain logged in until they explicitly sign out; no automatic expiry
  - *AC:* App opened after 30+ days of inactivity does not prompt re-authentication
- **Sign out all devices** — revokes all active sessions for the account
  - *AC:* After "Sign out all devices", re-opening the app on any device requires re-authentication
- **Account deletion with data preservation** — account and personal data deleted; campaigns owned by the deleted user remain accessible with name shown as "[Deleted User]"
  - *AC:* Username confirmation required before deletion; after deletion the account cannot be recovered; campaigns the user owned are still visible to members

### P1 — Nice to Have

- **Linked accounts view** — profile screen shows which OAuth providers are connected; user can link or unlink Discord and Apple from an existing account
- **Avatar via camera/gallery** — mobile-native image picker (photo library or camera); JPEG or PNG; placeholder shown when no avatar is set
- **Display name** — separate free-text field from username; shown in party cards and campaign headers; not required to be unique
- **Real-time username availability indicator** — inline feedback while typing (available / taken / invalid characters) before form submission

### P2 — Future Considerations

- **Apple Sign-In requirement for App Store** — if the app is submitted to the iOS App Store with any third-party social login present, Apple Sign-In is required by App Store guidelines; it is included in v1 but this note ensures it is not removed in future auth refactors
- **2FA** — could be added as an optional security layer for email/password accounts; OAuth paths already carry their own
- **Session management dashboard** — a list of active sessions (device, last seen, location) that the user can individually revoke

## Sign-Up & Onboarding

Three sign-up methods: **email/password**, **Discord OAuth**, and **Apple Sign-In**. All three are presented on the sign-up screen with equal prominence.

**Email/password sign-up** collects email and password only. After submission, the user lands immediately on a **username setup screen** — a dedicated step they cannot skip — where they set their unique username and display name. Once submitted they enter the app.

**Discord and Apple sign-up** skip the email verification banner (their accounts are inherently verified) and go directly to the username setup screen if it's their first time, or straight into the app on return visits.

**Email verification** is a soft gate. Email/password users who haven't verified see a persistent banner in the app: *"Verify your email to join campaigns."* Campaign-related actions (joining or creating a campaign) are locked until verified. All other app features are accessible. The banner shows a "Resend email" link.

---

## Login & Session Management

The login screen offers the same three methods as sign-up: email/password, Discord, and Apple. A "Forgot password?" link is visible below the email/password fields.

**Password reset flow:**
1. User taps "Forgot password?" and enters their email
2. A 6-digit OTP is sent to that address
3. User enters the code in-app (with a "Resend code" option after 60 seconds)
4. On valid code, user is prompted to set a new password
5. On success, they are logged in automatically

**Sessions persist indefinitely** — users stay logged in until they explicitly sign out. The Profile screen includes a **"Sign out all devices"** option that revokes all active sessions, for cases where a device is lost or stolen.

---

## Profile

The profile screen is accessible from the main navigation. Editable fields:

- **Username** — unique handle used for campaign invites; must be unique across all users; changing it updates all references (e.g. DM invite lookups)
- **Display name** — free-text name shown in the UI (party member cards, campaign headers, etc.); not required to be unique
- **Avatar** — set via mobile-native picker (photo library or camera); JPEG or PNG; if no avatar is set, a default placeholder (initials or generic icon) is shown throughout the app

The profile screen also shows:
- Linked accounts (Discord / Apple) — with the ability to link or unlink each
- **Sign out** button
- **Sign out all devices** button
- **Delete account** link (destructive, placed at the bottom with a warning)

**Account deletion flow:** tapping "Delete account" opens a confirmation sheet explaining: *"Your account will be deleted. Your characters and personal data will be removed. Campaigns you own will remain accessible to your players with your name shown as '[Deleted User]'."* The user must type their username to confirm. On confirmation the account is deleted immediately — campaign data is preserved.

## Edge Cases Summary

| Scenario | Behavior |
|---|---|
| Username taken at sign-up | Inline error shown in real time; user must choose a different username before proceeding |
| Email already registered at sign-up | Inline error prompts user to log in or reset password instead |
| Discord/Apple account already linked to existing account | Log in to the existing account; no duplicate account created |
| Unverified user tries to create/join a campaign | Action blocked; banner explains verification is required with a "Resend email" link |
| OTP entered incorrectly | Inline error; user can retry or request a new code after 60 seconds |
| OTP expired before entry | Inline error with "Resend code" prompt |
| User changes username | All references (campaign members, invite lookups) update immediately |
| Account deleted while character is active in a campaign | Campaign data and characters preserved; user's name shown as "[Deleted User]" in party views; DM can remove the deleted user from the campaign |
| User attempts to sign back in after deletion | Login rejected with "No account found" message |
